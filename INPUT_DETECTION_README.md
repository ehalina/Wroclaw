# Решение проблемы с планшетами - Определение типа ввода

## Проблема
На планшетах сайт открывался в десктопной версии, но элементы управления становились недоступными из-за невозможности наведения курсора.

## Решение
Реализовано определение типа ввода по возможностям указателя (hover/pointer) вместо ширины экрана или User-Agent.

## Файлы решения

### 1. `input_detection.js`
Основной скрипт определения типа ввода:
- Определяет тип устройства по медиа-запросам `(hover: hover) and (pointer: fine)`
- Добавляет соответствующие классы и data-атрибуты к `<html>`
- Сохраняет настройки в localStorage
- Поддерживает ручное переопределение режима

### 2. `input_compatibility.css`
Дополнительные стили для совместимости:
- Медиа-запросы для разных типов устройств
- Улучшения для планшетов и гибридных устройств
- Поддержка accessibility (prefers-reduced-motion, prefers-contrast)
- Обратная совместимость со старыми браузерами

### 3. Обновленный `common_tumski.css`
- Заменены медиа-запросы по ширине экрана на hover/pointer
- Десктопные устройства: элементы по наведению
- Тач-устройства: элементы всегда видны

## Как это работает

### Десктопные устройства
```css
@media (hover: hover) and (pointer: fine) {
    /* Элементы управления скрыты по умолчанию */
    .custom-cursor { opacity: 0; }
    
    /* Показываются при наведении */
    .custom-cursor-area:hover .custom-cursor { opacity: 1; }
}
```

### Тач-устройства
```css
@media (hover: none), (pointer: coarse) {
    /* Элементы управления всегда видны */
    .custom-cursor { opacity: 1 !important; }
}
```

## Преимущества

1. **Точное определение**: Не зависит от ширины экрана или User-Agent
2. **Универсальность**: Работает на всех устройствах
3. **Гибридные устройства**: Правильно определяет Surface и подобные устройства
4. **Обратная совместимость**: Fallback для старых браузеров
5. **Accessibility**: Поддержка пользователей с ограниченными возможностями

## Тестирование

### На десктопе
- Элементы управления скрыты
- Появляются при наведении мыши
- `data-input-type="desktop"` в HTML

### На планшете
- Элементы управления всегда видны
- Работают по тапу
- `data-input-type="touch"` в HTML

### На гибридном устройстве (Surface)
- Приоритет hover (десктопный режим)
- Элементы по наведению
- `data-input-type="desktop"` в HTML

## Ручное переопределение

Пользователь может принудительно переключить режим:
```javascript
// Переключить на тач-режим
localStorage.setItem('input-type-override', 'touch');
location.reload();

// Переключить на десктоп-режим
localStorage.setItem('input-type-override', 'desktop');
location.reload();
```

## Отладка

Для отладки раскомментируйте в `input_compatibility.css`:
```css
[data-input-type] body::before { display: block !important; }
```

Это покажет текущий режим в верхнем левом углу страницы.

## Совместимость

- ✅ Все современные браузеры
- ✅ iOS Safari
- ✅ Android Chrome
- ✅ Edge на Surface
- ✅ Старые браузеры (с fallback)

## Результат

Теперь на планшетах сайт автоматически открывается в тач-режиме с видимыми элементами управления, что решает проблему недоступности интерфейса.
